# DiagKit — agent notes

- The manifest is the product contract: `manifest.json` is written LAST, is named in no entries array (it cannot hash itself), and its shape is documented in the header and README. Any shape change needs the header, README, PARITY and the manifest tests changed in the same commit — support flows parse this file.
- Caps are enforced TWICE on purpose: once in `plan` from file sizes (so a 300 MiB bundle is rejected before a byte is read) and again on the streaming running totals in `collect` (so a file that grows mid-collection still cannot slip past). Removing either pass reintroduces a real hole — the plan-only version trusts stale sizes; the stream-only version reads hundreds of megabytes before it can say no.
- Entry names are derived ONLY from canonical paths (`entry_name_for` over `Component::Normal` parts). Never derive a name from the raw spec string: a spec path containing `..` would put traversal into the bundle. `extra_text` names go through `validate_entry_name`, and `manifest.json` is pre-seeded in the taken set so even a derived name can't claim it.
- Collisions suffix (` (2)`, ` (3)`), never overwrite and never drop: two entries sharing one name in a ZIP makes half the bundle unreachable by name. Caller-chosen extra names that collide are an error instead — the caller picked that name and should fix it, silently renaming their `notes.txt` would be worse.
- The bundle is written to a temp sibling and renamed into place. A failed collection must leave NOTHING at `output_zip` — a partial zip at the real path reads as "the bundle" to whoever picks it up next.
- A missing input is an error, never a skipped entry: a diagnostics bundle silently missing its main log wastes the whole round trip it exists to save. Same for `file_info` paths and directory roots. (Unreadable SUBdirectories inside a listing are the one documented exception — the listing is best-effort below the root.)
- `platform::version_strings` returns `Ok(None)` off Windows BY DESIGN — the spec promises "plain size+sha256 elsewhere", so None is the correct result there, not ERR_NOT_SUPPORTED. Do not "fix" it into an error.
- ZIP stays STORED (method 0) until the ROADMAP v0.2 compression item lands it behind the same central-directory contracts and tests. The writer's no-ZIP64 assumption is load-bearing and safe ONLY because the 256 MiB bundle cap keeps every size/offset a plain u32 — if the cap ever rises toward 4 GiB, ZIP64 comes first.
- Directory listings never read file contents and never follow symlinks (a symlink cycle must not be able to loop a walk). Listing work stops the moment the cap is exceeded — the `truncated` flag is the honest record of the cut.
- The JSON engine (src/json.rs) is the family design — duplicate keys in one object are a PARSE ERROR by design; do not "fix" that into last-wins.
- Zero dependencies; SHA-256 and CRC-32 are implemented in src/hash.rs and pinned by published test vectors. Changing either without changing the vectors' expected values in the same commit is not a thing that should ever happen.
- Gate: WinDevKit tools/gate.sh (fmt + clippy both targets + full tests). Check/clippy do not link — CI's real Windows build is the link gate, and the version-resource runtime is Unverified until an on-machine field pass runs it.
